## 一句话理解
按照 AWS Well-Architected Framework 评审工作负载，识别高风险问题并形成改进计划。
## 核心作用
- 依据 Operational Excellence、Security、Reliability、Performance Efficiency、Cost Optimization、Sustainability 六大支柱提问。
- 记录 High Risk Issues、Medium Risk Issues、改进建议和 Milestones。
- 支持团队反复评审架构随时间的改进。
## 工作中的应用场景
- 上线前对关键工作负载做架构评审。
- 对现有系统识别单点、权限、备份、成本和运维风险。
- 在架构变更后创建新 Milestone 比较进展。
## 工作原理
在工具中定义 Workload 并回答框架问题，系统根据选择显示风险项和改进建议；团队负责验证答案、安排整改并记录里程碑。
## Cloud Practitioner 考点
- Well-Architected Tool = 基于框架的工作负载架构评审。
## SAA-C03 考点
- 看到“六大支柱、架构评审、高风险问题、Milestone” → Well-Architected Tool。
- 它通常依赖人工回答和架构上下文，不是单纯自动扫描器。
## 常见误区
- 不会自动重新设计或修复架构。
- 评审结果的质量取决于输入是否真实完整。
- Trusted Advisor 的自动检查不能替代全面的工作负载评审。
## 易混淆服务
- **Well-Architected Tool**：问题清单式架构评审。
- **Trusted Advisor**：自动化最佳实践检查和账户级建议。
## 面试高频问题

- Trusted Advisor 与 Well-Architected Tool 如何互补？
## 重点记忆
**六大支柱 + Workload Review + Risk + Milestone → Well-Architected Tool。**
